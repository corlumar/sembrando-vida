# S1.3.7 — Saneamiento de Vistas, Layouts, Dashboards y Sidebars

## 1. Objetivo

Sanear la capa de presentación de la aplicación eliminando vistas, layouts, dashboards, sidebars y referencias visuales heredadas que ya no corresponden a la nueva baseline.

Esta subfase forma parte de **S1 — Saneamiento del repositorio**.

## 2. Estado

**Estado: CERRADO / VALIDADO**

Rama de trabajo: `refactor/saneamiento-repositorio`

El saneamiento principal de vistas y layouts fue ejecutado. Queda pendiente confirmar la eliminación de una referencia residual a `usuarios.create` en `auth/login.blade.php` y repetir la búsqueda final antes de marcar la subfase como cerrada.

## 4. Hallazgos

Las búsquedas sobre `resources/views` detectaron referencias heredadas a:

- CAC;
- sembradores;
- cultivos;
- cosechas;
- territorios;
- municipios;
- rutas;
- dashboards por roles;
- gestión antigua de usuarios;
- menús de CRM;
- proyectos;
- comercialización;
- configuración;
- enlaces ficticios mediante `href="#"`.

También se detectaron textos con problemas de codificación heredada.

## 5. Dashboard heredado

`resources/views/dashboard.blade.php` mostraba datos estáticos y conceptos del sistema anterior, entre ellos:

```text
Usuarios
Comunidades CAC
Sembradores
Cultivos
Resumen de producción
Registro de cosecha
```

### Decisión

**RECONSTRUIR**

No se elimina la vista porque la ruta `/dashboard` la utiliza actualmente.

Se definió sustituirla por un dashboard mínimo y veraz, sin funcionalidad simulada ni referencias de dominio retirado.

## 6. Dashboards por rol

Se eliminó completamente:

```text
resources/views/dashboards/
```

### Razón

Las rutas y controladores asociados ya no forman parte de la nueva baseline.

## 7. Vistas de usuarios heredadas

Se eliminó:

```text
resources/views/usuarios/
```

### Razón

Estas vistas dependían del antiguo `UserController`, de campos geográficos y de rutas que fueron retiradas previamente.

La administración de usuarios deberá reconstruirse posteriormente.

## 8. Sidebars heredados

Se eliminaron:

```text
resources/views/layouts/sidebar.blade.php
resources/views/layouts/partials/sidebar.blade.php
```

Los sidebars contenían enlaces o secciones para:

- usuarios;
- técnicos;
- CAC;
- sembradores;
- cultivos;
- cosechas;
- CRM;
- empresas;
- contactos;
- oportunidades;
- proyectos;
- tareas;
- calendario;
- comercialización;
- configuración.

Muchos enlaces utilizaban `href="#"`, por lo que representaban una interfaz adelantada a funcionalidades que no existen en la baseline actual.

## 9. Layouts duplicados

Se identificaron varias implementaciones concurrentes de layout:

```text
layouts/app.blade.php
layouts/adminlte.blade.php
layouts/admin.blade.php
layouts/navigation.blade.php
```

También existían navbar y footer duplicados.

### Decisión

Se estableció:

`resources/views/layouts/app.blade.php`

como **layout autenticado canónico**.

## 10. Archivos de layout eliminados

Se eliminaron:

```text
resources/views/layouts/admin.blade.php
resources/views/layouts/adminlte.blade.php
resources/views/layouts/sidebar.blade.php
resources/views/layouts/navbar.blade.php
resources/views/layouts/footer.blade.php
resources/views/layouts/partials/sidebar.blade.php
resources/views/layouts/partials/navbar.blade.php
resources/views/layouts/partials/footer.blade.php
```

Se conservaron:

```text
resources/views/layouts/app.blade.php
resources/views/layouts/guest.blade.php
resources/views/layouts/navigation.blade.php
```

`navigation.blade.php` permanece bajo revisión y no debe eliminarse sin comprobar primero las dependencias de Breeze y perfil.

## 11. Reconstrucción del layout canónico

`resources/views/layouts/app.blade.php` se definió como baseline mínima, sin sidebar, navbar o footer heredado.

## 12. Reconstrucción del dashboard

Se definió reemplazar `dashboard.blade.php` por una versión mínima con:

- saludo al usuario autenticado;
- mensaje de reconstrucción;
- cierre de sesión.

### Principio aplicado

Durante saneamiento se prefiere una interfaz mínima y verdadera a una interfaz visualmente completa pero basada en datos, módulos o funcionalidades inexistentes.

## 14. Referencia residual en login

La búsqueda detectó una única coincidencia restante en:

```text
resources/views/auth/login.blade.php
```

El bloque encontrado fue:

```blade
@can('manage-users')
  <a class="small-text" href="{{ route('usuarios.create') }}">
      ¿Eres administrador? Crear usuario
  </a>
@endcan
```

### Decisión

**ELIMINAR el bloque completo.**
