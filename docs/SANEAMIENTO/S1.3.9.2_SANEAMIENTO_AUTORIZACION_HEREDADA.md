# S1.3.9.2 — Saneamiento de Autorización Heredada

## 1. Objetivo

Eliminar reglas de autorización y referencias de roles que pertenecían al modelo anterior y que ya no tienen consumidores en la baseline saneada.

## 2. Estado

**Estado: CERRADO / VALIDADO**

Rama: `refactor/saneamiento-repositorio`

## 3. Hallazgo

`AppServiceProvider.php` todavía contenía:

```text
Gate::define('manage-users', ...)
```

La regla comprobaba el rol heredado `Administrativo`.

Los roles actuales son:

```text
Administrador
Usuario
```

## 4. Estado del consumidor

La interfaz había contenido `@can('manage-users')` y una referencia a `usuarios.create`.

Esos componentes ya habían sido retirados, por lo que el Gate quedó huérfano.

## 5. Decisión

Se eliminó de `AppServiceProvider.php`:

```text
Gate::define('manage-users', ...)
```

También se retiraron los imports de `Gate` y `User`.

## 6. Limpieza de vista

La búsqueda detectó una última referencia textual en `resources/views/auth/login.blade.php`, correspondiente a un comentario sobre administración de usuarios.

El comentario fue eliminado.

## 7. Validación de residuos

Se ejecutó:

```powershell
Get-ChildItem .\app,.\resources,.\routes -Recurse -File |
Select-String -Pattern 'manage-users|Gate::define|Administrativo' |
Select-Object Path, LineNumber, Line
```

Resultado:

```text
0 coincidencias
```

## 8. Validación de Laravel

Se ejecutó:

```powershell
php artisan about
php artisan route:list
```

Resultado:


La eliminación del Gate heredado no afectó la infraestructura ERP.

## 10. Validación Git

La futura autorización deberá construirse explícitamente sobre la nueva arquitectura.
