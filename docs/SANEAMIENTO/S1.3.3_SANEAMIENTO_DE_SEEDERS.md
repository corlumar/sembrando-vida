# S1.3.3 --- Saneamiento de Seeders

## 1. Objetivo

Sanear la capa de seeders después de retirar las migraciones y
componentes del dominio heredado, evitando que una ejecución de
`db:seed` o `migrate:fresh --seed` vuelva a introducir roles, usuarios
demo, subroles o referencias que ya no pertenecen a la nueva baseline.

Esta subfase forma parte de **S1 --- Saneamiento del repositorio**.

## 3. Hallazgos

### 3.1 DatabaseSeeder.php

`DatabaseSeeder.php` todavía contenía una llamada a:

`MasterSeeder::class`

Sin embargo, `MasterSeeder.php` ya había sido eliminado durante el
saneamiento anterior.

También conservaba una referencia conceptual a:

`roles y subroles`

Por tanto, el seeder principal ya no era compatible con el estado actual
del repositorio.

------------------------------------------------------------------------

### 3.3 RolesAndUsersSeeder.php

`RolesAndUsersSeeder.php` no contenía implementación funcional.

## 4. Decisión de saneamiento

Se decidió simplificar la estructura de seeders.

### Eliminar

-   `DemoUsersSeeder.php`
-   `RolesAndUsersSeeder.php`

### Crear

-   `RolesSeeder.php`

### Reconstruir

-   `DatabaseSeeder.php`

La estructura objetivo será:

``` text
database/seeders/
├── DatabaseSeeder.php
└── RolesSeeder.php
```

------------------------------------------------------------------------

## 5. Roles base

La nueva baseline utilizará inicialmente únicamente:

-   `Administrador`
-   `Usuario`

### Razón

Los roles anteriores estaban vinculados al dominio retirado.

No deben mantenerse solamente por compatibilidad histórica.

La autorización granular podrá evolucionar posteriormente mediante
permisos o capacidades específicas, sin reconstruir una jerarquía rígida
de roles y subroles.

------------------------------------------------------------------------

## 6. RolesSeeder

La responsabilidad de `RolesSeeder.php` será crear únicamente los roles
base del sistema.

Implementación definida:

``` php
<?php

namespace Database\Seeders;

use App\Models\Role;
use Illuminate\Database\Seeder;

class RolesSeeder extends Seeder
{
    public function run(): void
    {
        $roles = [
            'Administrador',
            'Usuario',
        ];

        foreach ($roles as $role) {
            Role::firstOrCreate([
                'name' => $role,
            ]);
        }
    }
}
```

El uso de `firstOrCreate()` permite que el seeder sea idempotente
respecto a los nombres de rol.

------------------------------------------------------------------------

## 7. DatabaseSeeder

`DatabaseSeeder.php` deberá quedar limitado a coordinar los seeders
vigentes.

Implementación definida:

``` php
<?php

namespace Database\Seeders;

use Illuminate\Database\Seeder;

class DatabaseSeeder extends Seeder
{
    public function run(): void
    {
        $this->call([
            RolesSeeder::class,
        ]);
    }
}
```

Ya no deberá contener referencias a:

-   `MasterSeeder`
-   subroles
-   usuarios demo
-   seeders del dominio anterior

------------------------------------------------------------------------

## 8. Usuarios demo

Se decidió no incluir usuarios demo en la baseline saneada.

### Razones

1.  Evitar credenciales de prueba permanentes.
2.  Evitar cuentas vinculadas al dominio anterior.
3.  Separar los datos mínimos de catálogo de los datos de desarrollo.
4.  Permitir posteriormente un mecanismo controlado para crear el primer
    administrador.

La creación del usuario administrador inicial deberá resolverse en una
fase posterior.

------------------------------------------------------------------------

## 9. Validación requerida

Después de aplicar los cambios deberá ejecutarse:

``` powershell
php artisan migrate:fresh --seed
```

La ejecución deberá:

1.  eliminar las tablas existentes;
2.  reconstruir las migraciones base;
3.  ejecutar `DatabaseSeeder`;
4.  ejecutar `RolesSeeder`;
5.  finalizar sin referencias a seeders eliminados.

Posteriormente deberá verificarse:

``` powershell
php artisan tinker
```

y dentro de Tinker:

``` php
App\Models\Role::all(['id', 'name']);
```

Resultado conceptual esperado:

``` text
1  Administrador
2  Usuario
```

Finalmente:

``` php
exit
```
