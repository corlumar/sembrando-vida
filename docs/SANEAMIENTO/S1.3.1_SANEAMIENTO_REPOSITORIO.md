-   seeders específicos del dominio anterior;
-   `Ruta.php`;
-   campos geográficos y de ruta directamente en `User.php`.

### User previo

`User.php` incluía, entre otros:

-   `estado_id`
-   `municipio_id`
-   `region_id`
-   `territorio_id`
-   `ruta`

La única relación Eloquent mostrada en el modelo era `role()`.

### Role

`Role.php` mantenía una estructura simple `Role -> users`, considerada
aprovechable como concepto.

### Rutas web

`routes/web.php` estaba reducido esencialmente a:

-   redirección `/` → `dashboard`;
-   `/dashboard` protegido por `auth`;
-   carga de `routes/auth.php`.

No se encontraron allí rutas principales del dominio anterior.

### Dependencias heredadas detectadas

Las búsquedas mostraron referencias del dominio anterior en:

-   `AdminDashboardController`
-   `UserController`
-   `StoreUserRequest`
-   `LoginResponse`
-   `User.php`
-   `Ruta.php`
-   vistas de usuarios
-   dashboard
-   dashboards administrativos
-   layouts
-   sidebars

Las coincidencias de "Ruta/Rutas" dentro de `Core`, comandos ERP,
templates y `Modules/Organizacion` no se consideran automáticamente
parte del dominio heredado, ya que varias se refieren a rutas web/API.

### Middleware

Se detectó `RoleMiddleware` y un alias `role` en `app/Http/Kernel.php`.

A la vez, `bootstrap/app.php` utiliza la configuración moderna de
Laravel y su bloque `withMiddleware()` estaba vacío.

Esto deja pendiente sanear la coexistencia de configuración heredada de
middleware con el bootstrap actual.

## 6. Componentes que no deben eliminarse por coincidencia nominal

Durante las búsquedas aparecieron palabras como "Ruta" o "Rutas" dentro
de:

-   `app/Core`
-   comandos ERP
-   templates de módulos
-   `app/Modules/Organizacion`

Estas coincidencias requieren interpretación semántica. "Rutas web" y
"Rutas API" no equivalen al modelo heredado `Ruta`.

Por tanto, `Core`, `Platform` y `Modules` no deben someterse a borrado
automático por coincidencia de texto.

## 8. Criterio de cierre de S1

S1 podrá cerrarse cuando:

-   el árbol de trabajo esté controlado;
-   las migraciones sean coherentes y reproducibles;
-   `migrate:fresh` funcione;
-   identidad y autorización estén desacopladas del dominio anterior;
-   controladores y vistas heredados estén retirados o reconstruidos;
-   la configuración de middleware sea coherente con Laravel actual;
-   no queden duplicados conocidos;
-   las decisiones estén documentadas;
-   exista un commit verificable de cierre del saneamiento.
