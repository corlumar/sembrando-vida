# S1.3.8.1 --- Saneamiento de Rutas Web y Navegación Base

## 1. Objetivo

Sanear y validar la definición de rutas web de la aplicación, asegurando
que la baseline conserve únicamente rutas funcionales, coherentes con
los controladores y vistas vigentes, y sin dependencias de módulos
heredados eliminados durante las subfases anteriores.

Esta subfase forma parte de **S1 --- Saneamiento del repositorio**.

------------------------------------------------------------------------

## 2. Estado

**Estado: CERRADO / VALIDADO**

Rama de trabajo:

`refactor/saneamiento-repositorio`

------------------------------------------------------------------------

## 3. Situación inicial

Después del saneamiento de controladores, requests, respuestas y vistas,
`routes/web.php` mantenía únicamente:

-   redirección de `/` hacia `dashboard`;
-   ruta autenticada `/dashboard`;
-   carga de `routes/auth.php`.

Sin embargo, todavía se conservaban:

-   `ProfileController`;
-   vistas bajo `resources/views/profile`;
-   referencias a `profile.edit`, `profile.update` y `profile.destroy`;
-   navegación base de Breeze.

Las rutas de perfil ya no estaban definidas, por lo que existía una
inconsistencia entre la capa de rutas y los componentes conservados.

------------------------------------------------------------------------

## 4. Decisión arquitectónica

Se determinó **conservar el perfil genérico de usuario**.

La razón es que el perfil:

-   no depende del dominio funcional retirado;
-   forma parte de la infraestructura estándar de autenticación;
-   conserva controlador y vistas válidas;
-   permite actualización de perfil, contraseña y eliminación de cuenta;
-   puede integrarse posteriormente con la reconstrucción de identidad y
    acceso.

Por tanto, no correspondía eliminar `ProfileController` ni las vistas de
perfil.

La acción correcta fue **reconectar sus rutas**.

------------------------------------------------------------------------

## 5. Rutas de perfil restauradas

Se incorporaron nuevamente en `routes/web.php` las rutas autenticadas:

``` php
Route::middleware('auth')->group(function () {
    Route::get('/profile', [ProfileController::class, 'edit'])
        ->name('profile.edit');

    Route::patch('/profile', [ProfileController::class, 'update'])
        ->name('profile.update');

    Route::delete('/profile', [ProfileController::class, 'destroy'])
        ->name('profile.destroy');
});
```

También se incorporó:

``` php
use App\Http\Controllers\ProfileController;
```

------------------------------------------------------------------------

La estructura resultante de `routes/web.php` conserva:


Las rutas de autenticación continúan centralizadas en `routes/auth.php`.

## 11. Navegación base

La revisión de `resources/views/layouts/navigation.blade.php` confirmó
que la navegación conservada utiliza rutas genéricas y válidas:

``` text
dashboard
profile.edit
logout
```

También contiene sus equivalentes para navegación responsive.

No se detectaron referencias a:

-   CAC;
-   sembradores;
-   cultivos;
-   cosechas;
-   territorios;
-   tianguis;
-   gestión heredada de usuarios;
-   dashboards antiguos por rol.

Por tanto, `navigation.blade.php` no debe eliminarse en esta subfase.

## 12. Relación con AppLayout

Se verificó que:

``` text
app/View/Components/AppLayout.php
```

renderiza:

``` php
return view('layouts.app');
```

También se verificó que:

``` text
resources/views/profile/edit.blade.php
```

utiliza:

``` blade

```

y define:

``` blade

```

Este hallazgo no impide cerrar S1.3.8.1, ya que las rutas quedaron
correctamente saneadas y registradas.

La compatibilidad entre:

``` text
AppLayout
layouts/app.blade.php
navigation.blade.php
profile/edit.blade.php

$header
```

se analizará específicamente en **S1.3.8.2**.
